# Migration Guide: the System page shows when the API does not report its build

`/app/admin/system` exists to spot a broken rollout. A failed `GET <api>/meta` used to end as commit `unknown`, which
`buildsMatch()` never warns about: an API outage looked exactly like a local build, with no error and no way to ask
again. The page now shows the error alert "API-Build nicht abrufbar" with "Erneut versuchen" (found in a project,
DEV-4180; the Nuxt template gets the same change):

- the button stays mounted while it works and is busy (`aria-busy`) without `disabled`, so a keyboard user keeps the
  focus;
- a retry that fails as well says so with the time ("Letzter Versuch um 14:05:09 Uhr: weiterhin keine Antwort."), also
  through a live region, because in an outage the answer is instant and an unchanged page reads as a button that does
  nothing;
- a retry that succeeds removes the alert and moves the focus to the API heading instead of dropping it to `<body>`;
- while the API does not answer, the API row says "Keine Angaben, solange die API nicht antwortet." instead of
  showing a commit badge.

| Project                                 | What to do |
| --------------------------------------- | ---------- |
| Uses the template's `/app/admin/system` | Step 1     |
| Removed the page                        | Nothing    |

No dependency and no API change are needed.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Take over the page and its spec

Copy `src/app/admin/system-page.ts`, `system-page.html` and `system-page.spec.ts`. If you changed the page, take over
`apiFailed` (a `linkedSignal` that an error sets and only an answer clears), `retry()`, the effect that resolves a retry,
and the error alert from the template.

## Check it

`pnpm test` runs `system-page.spec.ts`. In the browser, stop the API and open `/app/admin/system` as an admin: the alert
appears, "Erneut versuchen" reports the failed attempt, and after starting the API again the alert disappears and the
focus is on "API (Backend)".
