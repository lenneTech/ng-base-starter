# Migration Guide: oxlint leaves the generated API client alone

`pnpm run generate-types` writes `src/api-client/` from the API's OpenAPI document. Two settings of the template
worked against each other there:

- `.oxlintrc.json` linted those files like project code, so `lint` reported whatever the generator emits. Measured
  against nest-server-starter 12.8.4 with @hey-api/openapi-ts 0.99.0: 36 findings in generated files, among them a
  `typescript/no-floating-promises` error in `core/serverSentEvents.gen.ts`. The pre-commit hook and the CI lint job
  failed on code nobody in the project wrote, and a hand fix was gone after the next `generate-types`.
- `.oxfmtrc.jsonc` ignored `src/api-client`, while the generator ran oxfmt on its output. oxfmt exits 2 on a path it
  ignores ("Expected at least one target file"), so every `generate-types` run ended with `Post-processor "Oxfmt"
  exited with code 2` and exit code 1, although the client had been written.

The template now ignores `src/api-client/**` in `.oxlintrc.json` and formats it instead of ignoring it in
`.oxfmtrc.jsonc`, the same arrangement as the Nuxt template (nuxt-base-starter 6e70a8f).

| Project                                                                      | What to do |
| ---------------------------------------------------------------------------- | ---------- |
| Uses `generate-types`                                                        | Step 1     |
| Has its own exception for the generated client already (an override, a path) | Optional   |

No dependency and no API change are needed.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Ignore the client in oxlint, format it with oxfmt, in all four places at once

The changes belong together. oxlint exits 1 ("No files found to lint") and oxfmt exits 2 when every path they are
given is ignored. With only some of the changes, `generate-types` or a commit that stages only the regenerated client
would still fail.

In `.oxlintrc.json`, at the top level next to `plugins`:

```jsonc
// Generated by `pnpm run generate-types` (openapi-ts.config.ts): a finding there can only be fixed in the
// generator, and a hand fix is gone after the next run. Type checking and formatting still cover it.
"ignorePatterns": ["src/api-client/**"],
```

In `.oxfmtrc.jsonc`, remove `"src/api-client"` from `ignorePatterns`.

In `openapi-ts.config.ts`, under `output`, drop `'oxlint'` from the post-processors:

```ts
postProcess: ['oxfmt'],
```

In `package.json`, add the flag to the lint-staged command for `src/**/*.ts`:

```json
"src/**/*.ts": ["oxlint --type-aware --fix --no-error-on-unmatched-pattern", "eslint --fix", "oxfmt"],
```

`ignorePatterns` also applies to a file passed by name, with and without `--type-aware`. lint-staged therefore skips
staged generated files in oxlint, and still lints the project files staged with them. `typecheck` still checks the
generated types the app imports. The generator now formats its output with oxfmt, so `format:check` covers the client
as well. If your project made its own exception for these files, replace it with these lines.

Then run `pnpm run generate-types` once, so the client is formatted.

### 2. Take over the test (optional)

Copy `tests/unit/oxlint-generated-client.test.ts`. It runs oxlint and oxfmt with your configuration on probe files,
over `src/` and on single files. It fails in four cases:

- `src/api-client/` is reported by oxlint;
- the lint-staged command exits 1 when only generated files are staged;
- oxfmt ignores `src/api-client/`;
- `postProcess` still runs oxlint.

```bash
pnpm exec vitest run tests/unit/oxlint-generated-client.test.ts
```

## Check it

`pnpm run generate-types` exits 0, and `pnpm run format:check` passes on its output. Afterwards, `pnpm run lint`
reports nothing under `src/api-client/`.
