# Migration: ng-base-starter 14.x → 22.0.0

22.0.0 is a rebuild, not an upgrade. The 14.x starter (Angular 14, `@nguniversal`, Bootstrap, Apollo/GraphQL,
`@lenne.tech/ng-base` 14) shares no code with it. Its last state stays available as commit `7b85967` and in the 14.x
tags.

## Who is affected

Projects generated from ng-base-starter 14.x (Angular 14 with `@lenne.tech/ng-base` 14.x). They do not update in
place: there is no `ng update` path from 14 to 22 for this template, because the old starter depends on APIs the
backend no longer serves (GraphQL introspection auth, legacy JWT endpoints, which nest-server 12 answers with 410).

## What changed

| 14.x                            | 22.0.0                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------- |
| Angular 14, NgModules, zone.js  | Angular 22, standalone, zoneless, OnPush by default, signals                          |
| `@nguniversal/express-engine`   | `@angular/ssr` (`AngularNodeAppEngine`), render mode per route                        |
| Bootstrap 5, SCSS               | Tailwind CSS 4, `@lenne.tech/ng-base/ui`                                              |
| Apollo/GraphQL, legacy JWT auth | REST, Better Auth (`/iam`), cookie and JWT mode                                       |
| `environment.*.ts` per stage    | `NG_*` runtime variables, read by the server per request                              |
| Karma/Jasmine                   | Vitest, Playwright E2E                                                                |
| npm, husky, prettier, eslint    | pnpm 11, simple-git-hooks + lint-staged, oxfmt, oxlint + angular-eslint for templates |
| `dist/app/server/main.js`       | `.output/server/index.mjs` (the lt-monorepo contract)                                 |

## How to move a project

1. Generate a fresh project with `lt fullstack init --frontend angular` (or `lt frontend angular`).
2. Move your feature code over feature by feature, rewriting templates to native control flow, components to
   signal inputs/outputs and forms to Signal Forms. The Angular CLI MCP (`ng mcp`, in `.mcp.json`) and
   `ng generate @angular/core:control-flow` / `signal-input-migration` help for code that stays close to the old one.
3. Replace GraphQL calls with the generated REST client (`pnpm run generate-types`).
4. Replace `environment.*.ts` values with `NG_*` variables (see `.env.example`).
5. Run `pnpm run check` until it is green.
