# Migration Guide: the 2FA page says why a second factor was refused

Better Auth refuses a second factor for reasons other than a wrong code: an expired challenge
(`INVALID_TWO_FACTOR_COOKIE`), too many attempts on one challenge (`TOO_MANY_ATTEMPTS_REQUEST_NEW_CODE`) and a
temporarily locked account (`ACCOUNT_TEMPORARILY_LOCKED`). They carry no `#…_0000:` error code, so `/auth/2fa` showed
each as "Code ungültig", and the user retried a code that could never work. The page now says what happened, sends the
user back to the sign-in (with `?redirect=`) for a spent challenge, and asks them to wait during a lock. Same texts as
the Nuxt template (nuxt-base-starter #38).

Error toasts also share one rule now, `src/app/shared/error-text.ts`: a message with an error code is translated, a
project's own `#PROJ_0001:` included (the pages tested only for `#LTNS_` before), every other message gets the page's
German text.

| Project                                            | What to do |
| -------------------------------------------------- | ---------- |
| Uses the template's `/auth/2fa` and security pages | Steps 1-2  |
| Replaced the 2FA page with its own                 | Step 1     |

No dependency and no API change are needed.

## Upgrade steps (existing project)

In an `lt fullstack` monorepo, the steps happen in `projects/app/`.

### 1. Take over `errorText`

Copy `src/app/shared/error-text.ts` and `error-text.spec.ts`. In `src/app/settings/security-page.ts` and
`backup-codes-dialog.ts`, let the private `errorText(message, fallback)` call it:

```ts
return errorText(message, (text) => this.errors.translateError(text), fallback);
```

### 2. Take over the 2FA page

Copy `src/app/auth/two-factor-page.ts` and `two-factor-page.spec.ts`, or add the `TWO_FACTOR_REFUSALS` map and the
`refusal` branch of `verify()` to your copy.

## Check it

`pnpm test` runs `two-factor-page.spec.ts`: a wrong code still reads "Code ungültig", an expired challenge returns to
`/auth/login?redirect=…`, a lock stays on the page.
