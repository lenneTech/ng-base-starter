## Create a project

```bash
npm i -g @lenne.tech/cli

lt fullstack init --frontend angular   # monorepo with API (projects/api) and app (projects/app)
lt frontend angular                    # the app on its own
```

The CLI copies this repository into `projects/app` (or the directory you name) and removes what only the starter
needs: `.github/`, `CHANGELOG.md`, `extras/`, `migration-guides/` and its own docs pages. The project gets its own
`package.json` identity: version `0.0.0`, no `repository`, and the name `app` in a fullstack project or the
directory name on its own. On its own it keeps `pnpm-lock.yaml`; in a fullstack project the monorepo's root lockfile
replaces it.

## Requirements

- Node `^22.22.3 || ^24.15.0 || >=26` (`.node-version`: 26)
- pnpm 11 (pinned in `package.json`)
- A [nest-server-starter](https://github.com/lenneTech/nest-server-starter) API on port 3000 and MongoDB

## Run it locally

In a fullstack project, `lt dev up` starts API and app behind HTTPS URLs (`https://<slug>.localhost`) and sets ports
and URLs itself. Use the URLs it prints.

Without the CLI:

```bash
pnpm install
cp .env.example .env
pnpm run dev            # http://localhost:3001
```

The app must run on port **3001** and the API on **3000**. The API's local defaults trust exactly that origin, and
2FA and passkeys fail with `403 INVALID_ORIGIN` on any other. `pnpm run dev` refuses a busy port instead of moving to
another one.

On a database without users, every page sends you to `/auth/setup`, where you create the first admin.

## Commands

| Command                         | What it does                                                                                                |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `pnpm run dev`                  | Dev server with SSR on port 3001, proxies `/api/*` and `/iam/*` to the API, loads `.env`                    |
| `pnpm run build`                | Production build into `.output/` (`NG_OUTPUT_DIR` moves it)                                                 |
| `node .output/server/index.mjs` | Runs the build (`PORT`, default 3001; the image sets 3000)                                                  |
| `pnpm test`                     | Unit tests: `ng test` for the specs in `src/`, Vitest for `tests/unit/`                                     |
| `pnpm run test:e2e`             | Playwright against a running API, see [Auth E2E suite](../e2e-auth.md)                                      |
| `pnpm run check`                | The full gate every commit must pass: audit, overrides, format, lint, tests, build, typecheck, server start |
| `pnpm run generate-types`       | Regenerates the API client in `src/api-client/` from `${NG_API_URL}/api-docs-json`                          |
| `pnpm run check:baseline`       | Compares the app with a fresh `ng new` of the pinned Angular CLI, after every `ng update`                   |

Run `pnpm run check` before every commit and fix every error, also the ones you did not cause.

## Working with coding agents

`CLAUDE.md` and `AGENTS.md` carry the same rules (Claude Code reads the first, Codex and other agents the second):
structure, conventions, auth rules, security and tests. `.mcp.json` registers the project's own Angular CLI as an MCP
server, so an agent can look up Angular best practices and documentation for the pinned version.
