## Folders

```text
src/
  main.ts, main.server.ts       browser and server bootstrap
  server.ts                     Express server: security headers, HTML no-cache, build identity, robots and sitemap,
                                NG_* runtime config, Angular engine (also the dev server's request handler)
  server/                       pure server helpers (unit-tested in tests/unit/server/)
  index.html, styles.css
  app/
    app.ts, app.config.ts, app.config.server.ts, app.routes.ts, app.routes.server.ts
    shared/                     cross-feature code (runtime config, small utilities)
    <feature>/                  one folder per feature area (home, auth, dashboard, settings, admin, ai, ...)
  api-client/                   generated by `pnpm run generate-types`, never edited by hand
  core/                         vendored ng-base (vendor mode only)
scripts/                        build, dev, check chain, type generation (plain Node, no install needed)
tests/unit/                     tooling and contract tests (Vitest, Node)
tests/e2e/                      Playwright specs and helpers (against a real nest-server-starter)
docs/                           project docs
```

Code is organised by **feature**, never by type: there are no `components/` or `services/` folders, and each file
holds one concept.

## Routes

The routes are the same as in nuxt-base-starter. Pages and the two layouts are lazy, so the initial bundle holds only
the root shell and the router. The render mode of each route is set in `src/app/app.routes.server.ts`.

| Path                                                                                                                | Page                                       | Access                                      |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | ------------------------------------------- |
| `/`                                                                                                                 | Home                                       | everyone                                    |
| `/auth/login`, `/auth/register`, `/auth/forgot-password`, `/auth/reset-password`, `/auth/verify-email`, `/auth/2fa` | Sign-in pages                              | guests                                      |
| `/auth/callback`                                                                                                    | End of a sign-in through a social provider | everyone                                    |
| `/auth/setup`                                                                                                       | First admin of a new system                | while the API has no admin                  |
| `/app`                                                                                                              | Dashboard                                  | signed in                                   |
| `/app/settings/security`                                                                                            | Password, 2FA, passkeys                    | signed in                                   |
| `/app/ai`, `/app/settings/ai`, `/app/settings/ai-prompts`                                                           | AI assistant and its settings              | signed in, while the API runs its AI module |
| `/app/admin`, `/app/admin/system`, `/app/admin/ai/*`                                                                | Administration                             | role `admin`                                |

The route guards read the `lt-auth-state` cookie, which the browser can change. They only decide what the UI shows;
the API decides what a user may do.

## Conventions

- **Angular:** standalone components, signals, `input()`/`output()`/`model()`, native control flow (`@if`, `@for`),
  `inject()` instead of constructor injection, OnPush and zoneless by default.
- **File names** follow the Angular style guide: `login-page.ts`, `login-page.html`, `login-page.spec.ts`, without
  `.component`.
- **Data loading** with resources (`httpResource`, the generated `…Resource()` functions, `resource()`). A template
  branches on `isLoading()`, `hasValue()` and `error()`.
- **Forms** with Signal Forms and the Valibot schemas of the feature, German messages.
- **Routes** are lazy (`loadComponent`/`loadChildren`) with German titles.
- **SSR:** no browser globals (`window`, `document`, `localStorage`) during server rendering. Inject `DOCUMENT`, check
  `isPlatformBrowser`, or use `afterNextRender`.
- **Styling:** Tailwind utility classes in templates only, no component style files, semantic color tokens only
  (`bg-primary`, `text-muted`). Dark mode is the `.dark` class on `<html>`. `src/styles.css` imports one stylesheet per
  ng-base component the templates use; a new component needs its import, and `tests/unit/styles-contract.test.ts`
  names the missing one.
- **UI labels** are German, code and comments English.
- **Tests first:** component and service specs next to the code (`*.spec.ts`), tooling and contract tests in
  `tests/unit/`, E2E with Playwright against a real API.

The full rules, including the auth rules shared with nuxt-base-starter, are in the project's `CLAUDE.md`.
