## Docker image

```bash
docker build --build-arg APP_VERSION_COMMIT=$(git rev-parse HEAD) -t app .
docker run -p 3001:3000 -e NG_PUBLIC_SITE_URL=… -e NG_PUBLIC_API_URL=… app
```

The image runs as a non-root user, listens on port 3000 and has a health check on `/`. `APP_VERSION_COMMIT` becomes
the build identity shown under `/app/admin/system`, so a stale container is easy to spot.

## What a stage needs

The same image runs on every stage; only the environment differs. Each stage sets at least `NG_PUBLIC_SITE_URL`,
`NG_PUBLIC_API_URL`, `NG_API_URL` and `NG_PUBLIC_APP_ENV` (see [Configuration](./3.configuration.md)).

- **Behind a reverse proxy** the SSR server trusts `X-Forwarded-Host` and `X-Forwarded-Proto`. The forwarded host must
  be an allowed host (the host of `NG_PUBLIC_SITE_URL`, localhost, or one in `NG_ALLOWED_HOSTS`); Angular answers 400
  otherwise.
- **Security headers** are sent by the server itself, see [Security headers](../security-headers.md).
- **Search engines:** every stage but production is noindex; `/app`, `/auth` and `/admin` are never indexed.
- **A stage without users** does not open the setup form over HTTP unless the API allows it. Open `/auth/setup` on
  the stage to see how to create the first admin there.
